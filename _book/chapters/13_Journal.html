16 September 2026 - Week 7 - ARCH/GARCH

First week after the vac, we had a make up lecture in the lab to make up for the missed lecture in week 3 to discuss ARCH & GARCH models (volatility models). These are commonly used in financial returns data which have conditional heteroskedasticity, which means that the variance in the data isn’t constant across the observed time period. There are periods of higher or lower volatility, or in other words, the variance depends on time \(t\). This is the variance equation, which describes the conditional variance at \(t\). This is used along with the mean equation, which describes the predictable component of a time series, to model the data. The mean equation can either be constant, or it ca be an ARMA model.

We learned to transform the data into the appropriate variable of interest, which is usually logarithmic return. We learned about the error terms (or innovations), which are used in our models.

Then we learned about the models themselves, starting with ARCH. The ARCH(q) model models the variance by summing up the squared past \(q\) error terms. GARCH(p,q) models then add a lagged conditional variance term, which makes the variance dependent on the past \(p\) variances. GARCH is used when volatility persists for an extended period. Persistence refers to how many periods it takes for the effect of a shock to disappear.

We also learned to identify if an ARCH or GARCH model may be needed by using an ARCH LM test to see if residuals (error terms) are dependent. We looked at several diagnostics to determine if an adequate model has been selected. Finally, we were introduced to the rugarch package, and were given some practical exercise questions (see Chapter 3).

This section was a bit more confusing, as the notes didn’t contain any examples or plots. I think I understand in theory, but it would be nice to have seen an example plot showing the predicted vs the actuals. It also would have been helpful to understand the differences with ARIMA, as I’m not sure what the difference will look like. It may help to perform ARIMA and GARCH on the same data set and plot the predicted fit vs the actual, to see which model follows the actual data better.

21 September 2026 - Week 8 - Time Series Regression

In this lecture we learned about using time series regression models, which are useful when we want to understand how are data came to be as it is, rather than forecasting which ARIMA focuses on.

In TS Regression, we have a normal linear regression model, but instead of the error terms being i.i.d and normally distributed, they are replaced by ARMA errors to account for the auto-correlation between errors. The error term \(v_t\) is dependent on the past error term in the form \(v_t = \phi v_{t-1} + e_t\). This means there are now 2 “error” terms, and the objective is to minimise SSE of the \(e_t\) errors.

We also learned about using generalized least squares to add an AR1 process for errors in R, and about interventions to improved the regression model.

We then looked at harmonic regression which is used for seasonal effects, but this was very difficult to follow at the time as it required an understanding of spectral analysis (which we only got introduced to in an informal lab session later that same week). You can use a sum of sin and cosine functions to model and cyclic time series, and look at the spectrum to see which frequencies explain most of the variation in the data.

We also saw that time series regression could be used in generalized additive models (GAMs), not just simple linear models by using splines, which allow for different error correlation structures. GAMs are useful when dealing with non-linear trends.

We will have to show how to calculate the \(e_t\) terms by hand (see Chapter 6), and will be given data to fit our models too.

I really enjoyed this section, as it brought together my understanding of time series data and combined it with what I’m already familiar with. I’m excited to try make a linear regression model, and to compare it with and without using ARMA errors.

28 September 2026 - Week 9 - State Space Models

This week we looked at State Space Models (SSMs). In state space models, we aren’t interested in the observations, but rather we are interested in some underlying unobservable signal that generates the observation. In other words, the observations are a function of a hidden state plus some noise, and we want to estimate the hidden state at different points in time.

This was a bit confusing at first to conceptualise, but once we were shown a directed acyclic graph, and an example plot which showed the “hidden” state that observations were produced from, it became much more clear. The variable of interest is the state, not the observations. The observations are independent of each other, and ony depend on the state at that time. The states are only dependent on the state immediately before it.

The state space model uses an observation equation, which is a function of the state, and a state equation, which is a function of the previous state. We focused on three special SSMs, which are the Random Walk plus Noise, Local Linear Trend, and the Basic Structural Model. We were shown examples and some practical code. Finally, we ended off with regression with time varying coefficients, by adding explanatory variables to the observation equation. We will look at Kalman Filters next week.

There is a prac to do and a tutorial. See Chapter 7. This section definitely looks the most challenging technically so far, so I need to make sure I practice. I haven’t kept up with the exercises and practice so far, and I’m running short on time, and the Honours Project is due soon.

5 October 2026 - Week 10 - Kalman Filter

The Kalman Filter is used to help find estimates for the underlying signal in a state space model. It works like a baesian approach, where we predict the state (the prior), predict the observation (the likelihood), and then update the state estimate after seeing the next observation (the posterior).

The algorithm used is a bit complicated, and it’s a bit unclear exactly how it relates to Bayes. In Bayes you take a prior distribution, and then multiply by the likelihood given the data. In the Kalman Filter, you update one observation at a time. You find the difference between your estimate of the observation and the actual observation (the error), and use that to adjust your belief of the underlying distribution. The adjustment is the error multiplied by the Kalman Gain. The Kalman Gain is calculated using the one step ahead predictive distributions. If the gain is equal to 0, the posterior will equal the prior no matter what the error is. This occurs when there are missing (or NA) values in the data.

This is all very confusing, and will hopefully make more sense once I work through it. See Chapter 7.

We can use likelihood to estimate the two variance parameters, the variance of the two error terms. One is from the variance of the observation equation errors, and the other is from the state equation error variance.

We also have the Kalman Smoother, which works in reverse. It starts by using the Kalman Filter estimate of the state after looking at all the observations, and then recursively steps back through each estimate and smooths them out. The filter estimates follow the observations too much, and by smoothing it out, you get a smoother, better estimate of the underlying state.

12 October 2026 - Week 11 - Hidden Markov Models

Is this the last lecture? I can’t believe how fast the year has flown by. The last section in the course outline is Hidden Markov Models (HMMs) and we finished the slides on it in this lecture.

Like State Space Models, Hidden Markov models are interested in the underlying state or data generating process, but can only observe the data. The difference is that in Markov models, the underlying states are discrete and finite. This is nicely illustrated using a transition diagram of a coin toss example.

In addition to a transition diagram, we can make a transition probability matrix (TPM) to the the probabilities of the state staying or moving to each other state. The hidden states have to be discrete, but the observations (or outcomes) can be discrete or continuous.

This works very similarly to SSMs, so I found the concept fairly easy to grasp initially. The math was a bit harder to understand how it worked in this context. The joint probability is equal to the product of the conditional probabilities. In the Directed Acyclic Graph, this means the joint probability of the nodes is the product of the conditional probability of all nodes conditional on their parent nodes.

We looked at mixture models which were the sum of multiple underlying distributions. These relate to HMMs when we have a dependent mixture model, the probability of being in a state at time \(t\) depends on the state at time \(t-1\). You multiply state probability by the conditional probabilities of an observation, sum them all up and take the product over all observations to get the likelihood.

In HMM we have a transition probability, and an emission (or observation) probability. With some very complex math, we use likelihood to estimate the transition probability matrix and the parameters of each states distribution. We looked using likelihood at first a single observation, then with two observations.

The math in this section is a bit beyond me, but I understand how the HMM works and when it gets used. The tutorial exercises will help me practice applying the math by hand, but I’m confident I can do the appropriate coding in R. See Chapter 8.
